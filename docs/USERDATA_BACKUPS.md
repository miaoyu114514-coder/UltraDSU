# userdata 备份管理

从设置中的“管理 userdata 备份”查看全部槽，也可以从槽编辑页进入本槽列表。两种 UI 均支持，仅在开启并授权 Root 后显示入口。需要在主系统、没有 DSU 安装任务时使用。

## 列表与删除规则

- “当前 userdata”指槽当前绑定的逻辑 userdata 镜像。所有槽的这项数据始终受保护，不能从管理器删除；槽暂未启动也不代表分区闲置。
- `userdata_gsi.img` 与 `.0000` 等分片组成同一个在用镜像，不会把其中某片当作未使用分区。列表按逻辑 userdata 展示容量，无法确认时显示未知并保护备份。
- “扩容备份”来自应用的 `/data/adb/ultradsu/growth/<slot>/`。一个事务中的完整原始备份、未完成副本和恢复记录作为一组管理；显示槽名、容量、更新时间及保护原因。
- 扩容已完成、已经回退，或仍停留在未替换原分区的备份阶段，可以选择删除。没有恢复记录的独立遗留副本也可以清理；未提交的恢复记录、未知文件、损坏记录、待修复标记或未完成的启动恢复记录会阻止删除。
- 扩容进入替换、原始还原、回退或恢复失败阶段时，完整恢复备份受保护，需先在槽编辑页完成恢复。不会因为该副本没有被挂载，就允许删除唯一恢复来源。
- 删除前会确认槽名、备份容量和失去回退能力的后果。删除后在用 userdata、系统分区和其他槽不变。已有扩容预检缓存随即失效，避免继续展示已删除备份的回退操作。

本功能管理已有的扩容备份，没有新增手动创建任意快照或导入未知 userdata 的入口。整槽删除和清空重建仍是各自独立、需要确认的操作。

## 后端限制

列表与清理不调用原生扩容工具，不需要解封装 userdata 密钥。razr 2022 / Android 14 的默认槽和命名槽已只读核对；扩容尚未支持不会妨碍备份列表本身工作。

Root 桥接提供只读的 `userdata-backups`，以及限定槽标识、固定 `growth` 类型和列表版本标识的 `userdata-backup-delete`。不接收任意文件路径，不提供删除 `current` 类型的实现。

每次删除都在应用 Root 操作锁下重新检查主系统/安装状态、全部已注册槽的在用镜像、维护标记、事务阶段和文件身份。列表版本标识包含固定文件集合的身份、尺寸、更新时间及小型恢复记录摘要，不为列出备份全盘读取数十 GiB。旧列表与实际文件不符时，要求刷新并重新选择。

符号链接、目录越界、与在用镜像指向同一文件的硬链接均拒绝。只删除固定备份文件，不递归删除目录、不调用 gsid 的分区删除接口。先清理副本，再移除恢复记录，并同步目录；清理中断可以重新读取残留状态。其他 Root 工具不参与本应用的操作锁，维护时不要并发操作同一槽。

已注册标准内部槽及独立备份是当前支持范围；无法核实的外部/非标准布局保守保护。可识别槽的协作准备会在清理后尝试一并移除；失败时显示单独提示，原槽密钥不删除。

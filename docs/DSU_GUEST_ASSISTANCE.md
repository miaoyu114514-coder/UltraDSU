# 客体协作扩容

当目标槽可启动，但较旧的主系统因 KeyMint 版本绑定无法使用同一槽位密钥时，可以先在客体完成加密交接，再回到主系统沿用完整备份与离线扩容。应用仍要求主系统 Android 16+ / arm64、Root、标准内部多槽布局及本机预检通过；本流程不绕过 KeyMint，也不修改原有密钥封装。

## 操作步骤

1. 主系统进入目标槽的编辑页，检查兼容性；对已适配的密钥解封装失败可选择“准备客体协作”。
2. 选择“启动客体进行协作”。在目标客体安装同一版本 UltraDSU，开启并授权 Root。
3. 客体概览页显示等待中的协作卡片。选择“加密采集协作信息”，成功后选择“返回主系统”。此阶段不重建或扩容 userdata。
4. 主系统再次检查目标槽。只有加密交接、文件系统与 FBE 密封记录预检均通过，才显示“客体协作已验证”及保留数据扩容入口。
5. 确认目标槽和更大容量后，执行完整原始备份、独立校验、分配、恢复、密文感知文件系统扩容及加密记录复核。
6. 启动客体核对文件与应用。完整备份及协作凭据保留；确认后清理备份时一并清理本次协作。

两种 UI 使用同一流程。Root 未授权时不显示协作入口。准备和采集使用应用内操作状态；实际扩容/回退沿用前台任务、悬浮进度与分阶段进度条。

## 加密交接与生命周期

- 主系统应用生成本次会话专用的 Android Keystore RSA-2048 私钥，要求硬件保护；私钥不导出到文件。Root 跨系统邮箱只保存公钥请求及加密响应，路径为 `/metadata/ultradsu/assist/<slot>/`，目录 0700、文件 0600。
- 客体辅助进程校验 DSU 启动状态、目标槽、默认 fstab 的槽位密钥目录、F2FS 及已适配的元数据加密格式，只读解封装已有元数据密钥与系统级 DE 密钥。它不读取用户 CE 密钥或个人文件。
- 客体在内存生成 AES-256-GCM 交接封装，用主系统公钥以 RSA-OAEP SHA-256 / MGF1 SHA-1 封装随机 AES 密钥。AAD 绑定协议版本、槽名、随机会话、密封密钥记录标识与公钥摘要。更换槽、会话、公钥或篡改响应均拒绝。
- 回到主系统后，由应用自己的 Keystore 私钥解开交接。明文仅经匿名标准输入管道交给 Root 桥接与原生子进程，不进入命令参数、环境、日志或磁盘。接收端核对当前槽的密封记录标识；缓冲区用后清零，相关 Root/原生进程关闭 dump。
- 交接只用于本槽预检、扩容和回退；原有密钥封装保持不变。离线工具继续区分元数据与 fscrypt 文件密文视图，并验证密封 FBE 记录。
- 完整恢复备份存在时，不允许替换或清理本次协作请求，防止删除恢复依赖。备份清理后，再删除跨系统密文响应和应用 Keystore 会话私钥。

## 丢失协作凭据后的回退

Android Keystore 凭据可能随应用数据清除或卸载而丢失。因此协作扩容的恢复记录标注 `assisted`，允许在无法再次解密文件系统时恢复完整原始备份。仍须在分配前核对原密封密钥标识、备份精确大小及独立 SHA-256，恢复后再次逐字节核对原始块映射。

只有上述原始字节恢复通过，才记录 `ROLLED_BACK_RAW` 并允许启动原客体核对数据；这不宣称主系统文件系统检查已经通过。普通非协作扩容仍维持原来的文件系统复核要求。备份篡改、槽位密钥标识改变或原始数据恢复不完整仍会阻止启动和备份清理。

协作不替代独立的离机备份，也不能使未适配的算法、硬件封装密钥或文件系统格式自动得到支持。测试结果与已覆盖设备见 [设备验收](DEVICE_TESTING.md)。

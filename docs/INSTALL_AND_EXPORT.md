# 安装流程与分区镜像提取

以下功能随公开预发布 `0.2.8-alpha.13` / code 24 提供，最低 SDK 仍为 Android 10 / API 29。

## 一次安装

创建槽配置并选择镜像后，槽卡片只保留一个“安装”入口。确认槽名和 userdata 容量后自动读取、识别压缩包、准备分区并继续安装。单镜像写入 system，多镜像按已支持的分区名处理；未知、重复分区或缺少 system 的新槽包拒绝安装。已准备镜像可以复用，取消或安装被拒绝时不必重新解包。

Alpha 13 起，安装或分区替换确认成功后，自动删除应用内对应准备目录（包括多分区安装 ZIP），保留分区名称、容量与来源信息。Root 刷新确认旧槽完整时，也会清理历史副本。失败、取消、未确认提交和待修复镜像保留；原始来源、真实槽和 userdata 回退备份不在清理范围。清理失败不把已完成安装标为失败，后续刷新重试。成功后再次安装需重新读取源文件；替换分区仍可正常导入新镜像。

文件删除限定为对应槽的已登记准备目录及兼容旧格式副本，拒绝越界路径及符号链接；没有递归清理整个应用目录。无 Root 的系统安装提交不等于成功，不能仅凭“已提交”自动删除系统安装器仍可能读取的文件。

Android 11+ 且 Root 已授权时使用内置槽安装引擎，内部命名槽仍受 gsid 兼容性限制。Android 10 的 Root 流程准备后交给系统安装器。无 Root 准备后自动显示 ADB 命令，仍需用户在电脑执行；应用不能自行获得系统签名权限。

## 取消与进度

进度气泡和通知显示分配、写入的分区名，例如 userdata、system、product。收起的气泡也显示阶段文字，进度为当前阶段，不是整个事务的预估比例。

准备与 Root 新槽分配、写入阶段可取消。应用通过独立 stdin 控制通道提出请求，Root 所有者在自己的 Binder 分配或写入尚未结束时调用 gsid 取消接口，等待调用结束后清理本次新槽，保留原有槽和已验证的准备文件。不使用全局 removeGsi 清理其他槽，不直接杀掉写入进程。清理失败会保留错误和未完成状态，不显示成功取消。

开始提交完成标记、恢复启动选择后暂时禁止取消，以完整完成提交。极晚的请求可能返回安装成功，结果以实际提交状态为准。现有分区替换、清空重建、保留数据扩容及回退不是此取消机制的适用范围。

交给系统安装器之后，安装进度及取消由系统 DSU 通知负责。无 Root 应用没有权限取消一个已提交的系统安装。

## 提取已安装分区

在主系统中开启 Root，进入槽编辑页的“槽内镜像”，在分区旁点击“提取”，选择保存位置。需要 Android 11+ 的槽镜像接口。支持已识别的 system、system_ext、product、vendor、odm、各 dlkm 及 userdata；不读取 boot、super、任意文件路径或密钥。

导出完整 raw `.img`，没有稀疏化或压缩。userdata 是原始加密块镜像，单个导出文件不包含使其独立恢复所需的全部密钥及槽元数据，不等同于现有扩容回退备份。目标必须有足够可用空间；云存储、可移动介质的速度和容量受提供方限制。

Root 仅只读打开本次临时映射，原始字节走 stdout，状态和进度走 stderr；应用写入文件选择器授予的位置，不需要额外一份完整临时镜像。两端按实际传输字节计算 SHA-256 并核对大小和摘要。取消、读取或目标写入失败均释放映射，尝试删除本次不完整文件；提供方拒绝删除时明确提示手动清理。正在运行、已映射、缺失、容量无效和待修复目标会拒绝提取。

## Moto 验证范围

Android 14 的已验证内部多槽回移 gsid 上，使用从未启动的专用合成槽验证准备→安装、1 GiB userdata 分配取消、system 流写入取消、提取成功及取消。64 MiB system 导出与输入镜像完整 SHA-256 一致。现有两个槽、容量、启动选择和启用状态保持不变，测试槽和应用缓存清理。

另通过真实系统文件选择器完整导出已有 los 槽的 2,210,029,568 字节 system，传输摘要校验通过；通过气泡取消 userdata 导出并检查不完整文件删除。没有启动合成测试系统，没有对现有 userdata 做扩容、重建或写入，也未验证第三方云文件提供方及真实断电。
